# CareBinder review

## Scope and verdict

CareBinder is an **implementation/prototype** at `18179e28d05b5630afb7456413b8c9954fd01436`. Health-record and medication features are not established as production-safe or clinically validated. Static sample only, not a complete audit; **runtime NOT RUN**. [Plan](REMEDIATION_PLAN.md).

## Findings ledger

- **CB-01 — High; confirmed static; high confidence.** [CI:18–23](https://github.com/knarayanareddy/CareBinder/blob/18179e28d05b5630afb7456413b8c9954fd01436/.github/workflows/ci.yml#L18-L23) runs `npm install` and `npm run build`, not the [manifest test script](https://github.com/knarayanareddy/CareBinder/blob/18179e28d05b5630afb7456413b8c9954fd01436/package.json#L6-L11). The sampled gate does not enforce lock consistency; actual drift, other workflows and branch protection are unverified. Reconcile the lock and gate tests and typechecking.
- **CB-02 — Medium; confirmed static; high confidence.** [AppointmentForm:17–24,42–43](https://github.com/knarayanareddy/CareBinder/blob/18179e28d05b5630afb7456413b8c9954fd01436/src/features/more/AppointmentForm.tsx#L17-L43) calls `setSaving(true)` before `await api.createAppointment` without a catch/finally. A rejected write leaves the button disabled and gives no local error; preserve input, report failure and reset state. Rejection was not reproduced.
- **CB-03 — High; confirmed static and owner decision; high confidence.** The [README:10–11](https://github.com/knarayanareddy/CareBinder/blob/18179e28d05b5630afb7456413b8c9954fd01436/README.md#L10-L11) says `simulated secure invites`; the [invite UI:76–82](https://github.com/knarayanareddy/CareBinder/blob/18179e28d05b5630afb7456413b8c9954fd01436/src/features/careteam/index.tsx#L76-L82) says `Invite sent`, and [sharing overview:55–59](https://github.com/knarayanareddy/CareBinder/blob/18179e28d05b5630afb7456413b8c9954fd01436/src/features/careteam/index.tsx#L55-L59) says members `have access`. The [share action:111–123](https://github.com/knarayanareddy/CareBinder/blob/18179e28d05b5630afb7456413b8c9954fd01436/src/features/careteam/index.tsx#L111-L123) sends fixed text without a URL or token. [api.ts:475–490](https://github.com/knarayanareddy/CareBinder/blob/18179e28d05b5630afb7456413b8c9954fd01436/src/core/api.ts#L475-L490) creates a local invite and syncs it; acceptance looks up a local token and creates a local member. Keep real sharing disabled until identity, delivery, acceptance, access and revocation are implemented and independently verified end to end.
- **CB-04 — High; confirmed static; high confidence.** [firestore.rules:19–38](https://github.com/knarayanareddy/CareBinder/blob/18179e28d05b5630afb7456413b8c9954fd01436/firestore.rules#L19-L38) allows profile `update` and all immediate subcollection `write` when `isOwner() || isMember(profileId)`, without role checks or ownership-field restrictions. A member, including one intended as viewer, could be authorized by these repository rules to modify profile data or membership documents; any authenticated user can create a profile without an ownerId constraint. This is conditional on those rules being deployed and membership existing; no exploit or live configuration was tested. Enforce immutable ownership and role-specific server-side access, then test denied writes and revocation.
- **CB-05 — High; confirmed static; high confidence.** [meds:82–102](https://github.com/knarayanareddy/CareBinder/blob/18179e28d05b5630afb7456413b8c9954fd01436/src/features/meds/index.tsx#L82-L102) shows `Scan Label` but `handleSimulateScan` fills `Lisinopril`, `10mg`, and `Take one tablet daily` after a timer. The [form:110–128](https://github.com/knarayanareddy/CareBinder/blob/18179e28d05b5630afb7456413b8c9954fd01436/src/features/meds/index.tsx#L110-L128) displays those fields and invokes save; [save:69–75](https://github.com/knarayanareddy/CareBinder/blob/18179e28d05b5630afb7456413b8c9954fd01436/src/features/meds/index.tsx#L69-L75) passes them to `createMedication`. This could be mistaken for a real label reading and saved; no actual harm is asserted. Remove fixed example prefill and require human verification; clinical stakeholders must approve any future real scan.
- **CB-06 — High; confirmed static; high confidence.** The [README:75–80](https://github.com/knarayanareddy/CareBinder/blob/18179e28d05b5630afb7456413b8c9954fd01436/README.md#L75-L80) claims `No Backend Server` and data `entirely locally`; [App.tsx:76–84](https://github.com/knarayanareddy/CareBinder/blob/18179e28d05b5630afb7456413b8c9954fd01436/src/App.tsx#L76-L84) calls `pullAllFromCloud`, while [firestoreSync:15–26,72–83](https://github.com/knarayanareddy/CareBinder/blob/18179e28d05b5630afb7456413b8c9954fd01436/src/core/firestoreSync.ts#L15-L83) contains write helpers and medication, record and appointment collection names. Actual transmitted fields, configuration and deployment are unverified. Map real flows before describing storage, consent or deletion.
- **CB-07 — High; confirmed static; high confidence.** [crypto.ts:49–62](https://github.com/knarayanareddy/CareBinder/blob/18179e28d05b5630afb7456413b8c9954fd01436/src/core/crypto.ts#L49-L62) exports the device key and writes its base64 representation to `localStorage` as `cb_dk`. Local encryption therefore does not by itself protect against same-origin script access to that key; a real compromise was not demonstrated. Define the threat model, key custody and recovery before making confidentiality claims.
- **CB-08 — Medium; confirmed static; high confidence.** [firestoreSync:15–26,85–102](https://github.com/knarayanareddy/CareBinder/blob/18179e28d05b5630afb7456413b8c9954fd01436/src/core/firestoreSync.ts#L15-L102) catches write failures as `non-critical` and continues per-collection pull errors silently. Users may not know whether data synchronized; actual conflict outcomes and calling paths were not tested. Define visible pending/error states and reconciliation.
- **CB-09 — High; confirmed static; high confidence.** [api.ts:62–70](https://github.com/knarayanareddy/CareBinder/blob/18179e28d05b5630afb7456413b8c9954fd01436/src/core/api.ts#L62-L70) uses the profile's `.first()` member and defaults to `'owner'` without matching the current identity; `requirePermission` uses that role. Separately, [api.ts:483–487](https://github.com/knarayanareddy/CareBinder/blob/18179e28d05b5630afb7456413b8c9954fd01436/src/core/api.ts#L483-L487) creates a member with `id: uid()`, while [firestore.rules:5–7](https://github.com/knarayanareddy/CareBinder/blob/18179e28d05b5630afb7456413b8c9954fd01436/firestore.rules#L5-L7) checks a membership document keyed by `request.auth.uid`. The identity mapping and effective access depend on other paths and deployed rules; no live exploit or failed sharing was demonstrated. Bind membership to authenticated identity and fail closed.
- **CB-10 — Medium; confirmed static; high confidence.** [meds:50–51](https://github.com/knarayanareddy/CareBinder/blob/18179e28d05b5630afb7456413b8c9954fd01436/src/features/meds/index.tsx#L50-L51) renders `MedDetailModal` with a possibly null medication; [meds:157–171](https://github.com/knarayanareddy/CareBinder/blob/18179e28d05b5630afb7456413b8c9954fd01436/src/features/meds/index.tsx#L157-L171) returns on null before calling `useToast()`, which invokes `useContext` in [toast.tsx:11–14](https://github.com/knarayanareddy/CareBinder/blob/18179e28d05b5630afb7456413b8c9954fd01436/src/core/toast.tsx#L11-L14). Changing selection changes hook invocation order, violating React's hook rules. Runtime consequences were not tested; move the hook before the return and test transitions through the actual UI.

## Five-discipline assessment

**Correctness/code:** CB-02, CB-05 and CB-10 affect specific UI paths. Reminder delivery, dose calculations and time zones are unverified; this is not medical advice.

**Automation/testing:** The historical [CI run](https://github.com/knarayanareddy/CareBinder/actions/runs/36902649034) succeeded at the pinned SHA; the sampled workflow only builds. Test quality and execution are unverified.

**DevOps/operations:** Sync is best-effort (CB-08); environment isolation, deployed rules, signing, monitoring, upgrades and restore remain unknown.

**OWASP/security:** CB-04, CB-07 and CB-09 establish repository-level authorization and key-custody concerns. [storage.rules:4–5](https://github.com/knarayanareddy/CareBinder/blob/18179e28d05b5630afb7456413b8c9954fd01436/storage.rules#L4-L5) limits that matched path to the authenticated user ID, but deployed rules and other storage paths are unverified. Auth/session, injection, uploads, secrets, dependency integrity, retention and deletion need targeted verification. No compliance certification is established.

**UI/UX/accessibility:** [AppointmentForm:28–41](https://github.com/knarayanareddy/CareBinder/blob/18179e28d05b5630afb7456413b8c9954fd01436/src/features/more/AppointmentForm.tsx#L28-L41) shows labels and inputs without `htmlFor`/`id` association in that excerpt. Test computed names, focus and screen readers. CB-03 and CB-05 need truthful copy.
